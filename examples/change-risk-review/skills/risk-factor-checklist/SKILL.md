# 算分之前：先问事实

分数是**事实的函数**。事实不全就去算分，等于在编数字。

## 必须问清的五类事实

| 事实 | 为什么要问 | 缺了会怎样 |
|---|---|---|
| 受影响面（模块/服务/表） | 影响面数量是主要权重项 | 分数严重偏低，且无法复核 |
| 执行环境（dev/staging/prod） | 每多一个环境加一项权重 | 会把多环境变更当成单环境 |
| 是否含数据迁移 | 单独一项高权重 | 最危险的一类变更会被低估 |
| 回滚方案（none/scripted/feature-flag） | 无回滚是高权重项 | 会把"不可回滚"评成中等风险 |
| 时间窗（高峰/非高峰）与负责人 | 两项独立权重 | 组织风险被忽略 |

## 缺事实时的正确反应

**不要**调用评分工具去"凑一个分数"。正确输出：

```
证据不足，暂不给分数。
缺：① 回滚方案（是否存在脚本） ② 是否包含数据迁移
补齐这两项即可评分；在此之前任何风险等级都是猜测。
```

## 常见错误（都是真实会犯的）

1. **先给结论再倒推因素**：先写「风险：中」，再找理由。顺序反了。
2. **把"我们做过很多次了"当证据**：这是信心，不是事实。历史次数与本次风险无关，
   除非能给出同类变更的失败率。
3. **替用户补事实**：用户没说的，就是没说的。标为缺失，别填。
