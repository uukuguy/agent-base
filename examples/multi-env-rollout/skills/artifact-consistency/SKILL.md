# 同一制品跨环境一致性检查

## 要证明的命题

> 三个环境里的**可执行制品**、**配置模板**、**技能集合**，其内容寻址摘要完全相同。

这是「换环境只应换值」里最难、也最容易被跳过的一环。跳过它的后果是：
env 之间的差异核对看起来很干净，实际上比的是**两份不同的东西**。

## 为什么必须是内容寻址摘要

| 你手上的标识 | 能证明什么 | 能不能用 |
|---|---|---|
| `myapp:latest` / `myapp:main` | 只能证明名字相同；同名可以被重新推一次 | ❌ **不能用** |
| 构建号 `build-4211` | 只在"构建号全局唯一且不可重推"时成立，靠流程保证 | ⚠️ 仅作索引 |
| `sha256:<64 位十六进制>`（镜像 digest / 制品摘要） | 内容变了摘要必变 | ✅ **这就是判据** |

所以本技能的判据只有一条：**三行必须是同一个 64 位十六进制摘要**。
`latest`、`main`、`stable` 这类可变标签在核对表里是**错误**，不是"简化写法"。

## 怎么做

1. **确定身份字段**（每类制品认一个，不要临时换）：
   容器 → 镜像 digest；配置 → 模板/产物摘要；技能 → 技能集合 + 内容摘要；依赖 → 锁文件摘要。
2. **从每个环境各自取证**，写清来源（部署记录 / 集群查询 / 制品库 API）。
   **来源是证据的一部分**：没有来源的摘要等于口头转述。
3. **横向比对**：三个摘要逐字符比较。只要有一个不同 ⇒ 结论是「不是同一份制品」，
   停止后续核对，先查清是哪一步把制品换掉了。
4. **用脚本机械复核**：把核对表交给
   `scripts/check-artifact-identity.mjs`（相对本技能目录），它逐行校验：
   摘要是否为内容寻址形态、是否用了可变标签、跨环境摘要是否一致、来源是否写了。

```bash
# 自检（脚本自带合法/非法样本）
node skills/artifact-consistency/scripts/check-artifact-identity.mjs --selftest
# 校验你自己的核对表
node skills/artifact-consistency/scripts/check-artifact-identity.mjs 制品核对表.md
```

## 输出（脚本认这个表头）

| 环境 | 制品标识 | 来源 | 备注 |
|---|---|---|---|
| dev | sha256:… | 部署记录 | 与 staging 同一次构建 |

摘要那列必须能归一成 `sha256:<64 位十六进制>`（可以省略 `sha256:` 前缀，但不能是别的形态）。

## 不要做

- 不要用 `latest` / `main` 当摘要，也不要在表里写"最新构建"这种描述。
- 不要从一个环境的结果推断另一个环境 —— 每个环境的摘要都要**独立取证**。
- 摘要不一致时不要继续比配置差异：前提已经不成立，后面的结论没有意义。
