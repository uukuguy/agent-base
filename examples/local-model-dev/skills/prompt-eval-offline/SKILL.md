# 提示词与输出的离线评测

## 为什么必须离线、必须重复

本地模型免费，但**慢且不稳定**：同一提示词两次输出可能不同。所以"这次看起来更好"不构成结论。
判据只有一条：**固定用例集 + 固定参数 + 重复 N 次 + 统计通过率**。

## 用例怎么写

一条用例 = 一个固定输入 + 一组**可机械判定的性质**。

> 关键：本地模型的措辞不稳定，**不要逐字匹配**。要判的是"必须出现什么、必须不出现什么、
> 必须是合法 JSON、必须发出工具调用"这类与措辞无关的性质。

三类判定，优先级从高到低：

| 判定 | 字段（见下表脚本） | 适合判什么 |
|---|---|---|
| 必须包含 / 不得包含某子串 | `requiresAll` / `requiresNone` | 关键词、禁用词、必须提到的字段 |
| 必须匹配某正则 | `mustMatch` | 格式骨架（形如 `E\d{4}` 的错误码） |
| 必须能 `JSON.parse` / 必须发工具调用 | `mustParseJson` / `mustCallTool` | 结构化输出、工具调用能力 |

确实无法机械判的（"解释是否清楚"），拆成几个**只想回答是/否的小问题**（rubric），
人工只回答这些小问题 —— 不要把整体印象当判定。

## 用例与结果的文件形状

用例 `cases.json`：

```json
{
  "cases": [
    { "id": "json-only",  "mustParseJson": true, "requiresNone": ["```"] },
    { "id": "tool-call",  "mustCallTool": true },
    { "id": "err-code",   "mustMatch": "^E[0-9]{4}$" }
  ]
}
```

结果 `results.jsonl`（一行一次运行，同一 `id` 可重复出现 —— 这正是"重复 N 次"的载体）：

```jsonl
{"id":"json-only","output":"{\"ok\":true}"}
{"id":"tool-call","output":"...","toolCalls":[{"name":"read"}]}
```

## 怎么跑

```bash
node skills/prompt-eval-offline/scripts/eval-check.mjs \
  skills/prompt-eval-offline/cases.example.json results.jsonl
```

它做的事很笨但可核对：逐条结果按用例声明的性质判通过/不通过，并给出失败原因；
任一用例**没有结果**、或任一次运行不通过，就退出码 1。
**用途是让自己知道哪条用例在什么性质上不稳**，不是让机器替你判断质量。

## 结论怎么写

- 只有**全部用例的全部运行都通过**，才能说"在本次用例集上稳定"。
- 否则写清：`N 次里 M 次通过，失败集中在「必须能 JSON.parse」这一性质上`。
- 换模型/换量化后重跑，**用同一份 cases.json**，否则两次的数字不可比。

## 不要做

- 不要只看一次输出就下结论。
- 不要用另一轮模型的输出当"标准答案"逐字比对。
- 不要把"格式对"当"内容对"：格式判定通过只说明它长得像，不说明它是对的。
