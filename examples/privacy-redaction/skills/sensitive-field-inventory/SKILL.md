# 敏感字段识别与分级

## 何时用

用户给的是**字段清单**（建表语句、数据字典、日志字段列表、样例记录），而问题是
「这份数据里有哪些敏感信息 / 有多敏感」。**先有清单才有后续审查** ——
没有清单就直接讨论脱敏方案，等于对着空气做决定。

## 怎么归类（四类，互斥且穷尽）

| 类别 | 判定标准 | 典型例子 |
|---|---|---|
| **直接标识符** | 单独一个字段就能唯一定位到一个自然人 | 身份证号、护照号、手机号、邮箱、银行卡号、设备唯一号（IMEI/IDFA）、精确人脸模板、账号 ID |
| **准标识符** | 单独不能定位，但**与其他字段组合**能唯一定位或大幅缩小范围 | 姓名、出生日期、邮编、性别、工作单位、就诊科室、入职日期 |
| **敏感属性** | 本身是个人信息，且一旦泄露/滥用会危及人身或财产安全、导致人格尊严受侵害 | 健康状况、生物识别、宗教信仰、行踪轨迹、金融账户、通信内容、不满十四周岁未成年人信息、性取向 |
| **一般属性** | 与个人关联很弱，或不构成个人信息 | 设备型号、页面配置、统计口径下的汇总值、内容无关的错误码 |

判定顺序是**从具体到抽象**：宁可从"能否唯一定位"往前推，也不要凭字段名想当然。

## 怎么定级（可识别性 × 敏感度）

| 级别 | 判据（满足任一即高） | 处置方向 |
|---|---|---|
| **高** | ① 类别 = 直接标识符；② 敏感属性本身；③ 准标识符在**本数据范围内**能唯一定位（如"生日+邮编+性别"在小样本里唯一） | 删除或不可逆替换；若要保留需单独授权 + 最小化 |
| **中** | 单个准标识符不足以定位，但与其他字段组合会显著缩小范围；或一般属性可用于画像 | 泛化 / 分箱 / 仅保留到统计分析所需粒度 |
| **低** | 无法关联到个人，且不承载敏感含义 | 可保留，但要在清单里写明"为什么是低" |

**依据一栏必须写清"为什么是这一类、这一级"**，而不是重复类别名。
写不出依据的字段，级别只能标「待确认」，并写清「需要什么（样例值 / 数据规模 / 使用目的）才能定级」。

## 输出

| 字段 | 所在材料 | 类别 | 级别 | 依据 | 处置建议 | 确定性 |
|---|---|---|---|---|---|---|

「确定性」只允许：`已核对` / `推断` / `未知`。
「推断」必须在依据里写清推的是什么；「未知」必须写清缺什么。

## 机械自检（可选但推荐）

本技能带一个只读的表格自检脚本，用来确认清单结构没跑偏（枚举合法、依据非空、
直接标识符不会被误定为低级别）：

```bash
node skills/sensitive-field-inventory/scripts/check-inventory.mjs 你的清单.md
node skills/sensitive-field-inventory/scripts/check-inventory.mjs --selftest
```

它只检查**形状与规则**，不判断你的定级对不对 —— 那是数据责任人的事。

## 不要做

- **不要凭字段名猜类别**。`user_name` 可能存的是脱敏后的假名，`remark` 可能写着病历。
  字段名只是线索，口径要看样例值或数据字典。
- **不要把"已加密 / 已哈希"当成"不需要分级"**。加密是可逆的保护手段，
  去标识化不等于匿名化；能拿到密钥的人仍然看得到原文。
- **不要为了填满表格而给"待确认"编一个级别**。留白比编造诚实。
- **不要顺手设计脱敏方案**。这一步只负责清点与分级，方法在 `redaction-plan-audit`。
