# 脱敏方案与残留风险核对

## 何时用

用户说「我们已经脱敏了 / 用了某某工具 / 只保留了后四位」，要你确认这个方案够不够。
**没有脱敏后样例就没有核对** —— 只有规则表时，你只能核对"规则与类别是否匹配"，
不得给出"达标"。

## 先要三样东西（缺哪样就说明缺哪样）

1. **脱敏规则表**：哪个字段 → 用什么方法（删除 / 掩码 / 哈希 / 泛化 / 分箱 / 假名化）；
2. **脱敏后的样例**：至少一行，用来验证规则是否真的按声明执行；
3. **使用目的与接收方**：给谁、用来做什么。**同一份数据，用途不同，达标线不同** ——
   内部分析与对外共享不是一回事。

## 方法是否匹配级别

| 原级别 | 最低要求 | 常见但不达标的做法 |
|---|---|---|
| **高（直接标识符）** | 删除，或**不可逆**替换（加盐哈希，盐是密钥且不进同一份数据） | 掩码保留后四位（仍可撞库）；用手机号直接哈希（无盐易被彩虹表反查）；"移到另一个表"（关联键还在，等于没脱） |
| **高（敏感属性）** | 单独授权 + 最小化，且默认不进入共享集 | 只删姓名，健康/行踪字段原样保留 |
| **中（准标识符）** | 泛化 / 分箱 / k-匿名（k ≥ 约定的阈值，并说明 k 是多少） | 逐字段看都"不够唯一"，忽略**组合**可唯一定位（生日 + 邮编 + 性别是经典反例） |
| **低** | 可保留，但写明它是低的依据 | 顺手也"脱"一遍，制造"全都处理过"的错觉 |

## 残留风险核对清单（逐条给出"是/否/无法判断 + 依据"）

| 风险 | 要看什么 |
|---|---|
| **链接风险** | 脱敏后的字段还能不能与外部数据（另一份名单、公开数据集）重新关联？ |
| **组合风险** | 多个"都不唯一"的字段合起来是否唯一定位？小样本里尤其容易 |
| **可逆性** | 哈希是否加盐、盐存在哪、谁有权限；假名映射表放在哪、谁能拿 |
| **残留副本** | 日志、缓存、导出文件、备份、消息队列里是否还有明文？（**最常见的事故来源**） |
| **元数据** | 文件名、大小、时间戳、自增 ID、序号是否泄露了被删字段的信息 |
| **推断风险** | 差分攻击：两次不同条件的发布结果相减能不能还原个体 |
| **粒度声明** | 泛化到什么粒度写清了没有（"年龄段"是 5 岁还是 10 岁一档） |

## 输出

| 字段 | 原级别 | 脱敏方法 | 是否达标 | 残留风险 | 复现识别所需的信息 | 确定性 |
|---|---|---|---|---|---|---|

「复现识别所需的信息」是本技能的核心产物：写清"要拿到什么，才能把这条记录重新对回某个人"。
写不出来时，写「在当前信息下未找到复现路径」——**这不是"不可能被识别"**。

## 纪律

- **去标识 ≠ 匿名化**。只要存在"用额外信息能重新关联"的路径，就必须写出来。
- **不接受"我们用了脱敏工具"作为依据**。工具是手段，要核对的是输出样例与规则是否一致。
- **没看到脱敏后样例时，结论最高只能到「规则层面匹配，样例未核对」**。
- **不要把"没找到残留风险"写成"没有残留风险"**。两者的确定性标注不同。

## 不要做

- 不要替用户决定"这样就够了"——达标线由使用目的与责任人定，你只给差距。
- 不要顺手产出可直接上线的处理脚本（本智能体是只读的，见 `agent.yaml` 的 `tools.deny`）。
- 不要在缺少使用目的时给"达标"结论；用途未知时，标「未知」并说明需要什么。
