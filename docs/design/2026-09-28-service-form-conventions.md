# 服务形态：基座给什么、上层做什么（接口约定）

> 2026-09-28 整理。**这份文档的作用是把"生产化剩余项"从含糊悬挂变成明确约定**：
> 基座的范围是"帮业务把想法验证走通"，生产化（多租户、并发调度、身份鉴权、成本对账）**不在基座范围内**
> （见 `CLAUDE.md` §1 与 `docs/13-developer-contract.md` §5）。但"不在范围"不等于"不说清楚" ——
> 这份文档写下：**基座已经给了哪些接缝（可验证）、上层必须自己做什么、每项今天能验什么**。
>
> 路线图里 E5（服务形态）· E7（隔离与故障边界）· E8（成本与审计）的剩余项按本文收口为**上层义务**。

---

## 1. 基座**已经给**的接缝（都可验证）

| 接缝 | 基座给的是什么 | 怎么验 |
|---|---|---|
| **受控容器执行** | 只读根、能力全丢、`no-new-privileges`、默认离线、**恰好两处只读绑定**（当前项目 + 产物） | `make verify-container AGENT_DIR=…`（失败自动归因）；同源检查拒绝旧镜像 |
| **运行期身份（run）** | 每次运行一个 run id；轨迹按 run 分组、`seq` 单调 | `make cost-report TRACE=…` · `make trace-view` |
| **会话身份（session）** | 基座持有会话 id：首跑建立、续跑标 `resumed`，并**核验**运行时实际用的 id | `make pi-session-selftest` |
| **结束标记** | `run.end` + 运行时给的原因（原话）⇒ 「正常跑完」与「中途掐断」可分辨 | 闸门 4 的 `smoke/run-end` |
| **审批留痕（fail-closed）** | 每条审批决定进轨迹 `approval.decision`（granted/denied/unavailable + 应答者）；无应答者 ⇒ 不执行 | 两侧 `*-verify-container-selftest` |
| **钩子的失败语义** | `hooks.onFailure: record/block` + `guardedHook()` 留痕；`block` ⇒ 本次运行判失败 | 闸门 1 `hooks/failure-policy` · 闸门 4 `smoke/hook-failures` |
| **用量归因（次数/时长）** | 每 run 的模型调用/工具调用/挂钟 + 钩子失败/审批次数 + 生效配置摘要 | `make cost-report TRACE=…` |
| **上层定制缝（不改产物）** | 运行期 overlay：镜像内加钩子/覆盖，仍进闸门 2 的集合断言 | `AGENT_OVERLAY_DIR`（`core/image/startup.mjs` 的 `applyOverlay`）· 派生镜像 `make image-derived` |
| **环境差异声明** | 本地 vs 容器的差异必须**显式声明**，未声明的差异判红 | `make env-check` |
| **产物自描述** | 清单记下定义/产物/渲染输入/生效配置四个摘要 + 能力/钩子/技能/连接器声明 | `/project` 命令 · `make project-info` |

## 2. 逐维度约定

### 2.1 会话生命周期

| | 内容 |
|---|---|
| 基座给 | 会话身份与落盘目录（`--session-dir`）；续跑及 `resumed` 留痕；结束标记 |
| **上层义务** | 决定会话**存在多久**、何时归档/清理、多个会话如何共享/隔离存储（基座只按调用方给的目录落盘） |
| 今天能验 | 续跑接对会话（`make pi-session-selftest`）；结束原因可见（`smoke/run-end`） |
| 上层实现后才能验 | 「会话被正确归档/清理」「跨机器共享会话存储」——需要上层的存储实现才有对象可验 |

### 2.2 并发

| | 内容 |
|---|---|
| 基座给 | **没有调度器**（一次调用 = 一次运行）。可并发的是"上层起多个进程/容器"，每个各有自己的 run/session/轨迹 |
| **上层义务** | 并发上限、排队、租户配额、限流、以及"并发下的资源隔离" |
| 今天能验 | 「两个并发运行各自留痕、互不覆盖」——基座侧只需各自的 `AGENT_TRACE_DEST`/`session-dir` 不同（上层的调度不在基座内） |
| 上层实现后才能验 | 配额与限流是否生效；并发下的公平性 |
| ⚠️ 明确不承诺 | 基座**不做**多会话共享状态、不做租户级资源治理。若上层需要"一次调用里跑多个会话"，那要新增接缝 —— 见 §3 |

### 2.3 状态外置

| | 内容 |
|---|---|
| 基座给 | 运行目录/会话目录由调用方指定（`AGENT_RUN_DIR`、`--session-dir`）；产物只读、运行期可写区明确（`/tmp`、runDir） |
| **上层义务** | 把会话/中间状态放到共享存储（对象存储、数据库、CSI 卷）并保证一致性与并发安全 |
| 今天能验 | 运行期可写面**只有**指定的那几处（容器 `--read-only` + `--tmpfs /tmp` + 只读绑定） |
| 上层实现后才能验 | 外置存储的读写正确性与并发语义 |

### 2.4 身份（"归因到人"的前置）

| | 内容 |
|---|---|
| 基座给 | **没有身份入口**（实测：轨迹能给出 agent/harness/run/session/生效配置摘要，但没有"人"）。这是 E8「归因到人」做不到的原因 |
| **上层义务** | 提供身份：调用方在起运行前把身份放进环境（如 `AGENT_ACTOR`）或在网关侧带会话头；`cost-report` 目前**明确报告"归因到人做不到"** |
| 今天能验 | 报告**如实说**归因不到人（不编造）——`make cost-report` |
| 上层实现后才能验 | 身份是否真的贯穿到每一次运行与每条审批 |

### 2.5 隔离与故障边界

| | 内容 |
|---|---|
| 基座给 | 容器级隔离参数（§1 第一行）；**钩子失败语义显式化**（`record`/`block`，都先留痕）；进程边界调用能力实现（业务代码崩溃不会带走会话：`kind: process` 由基座按退出码处理） |
| **上层义务** | 每租户一容器/进程（编排层）；插件崩溃的**兜底与重启**策略；跨租户的资源隔离 |
| 今天能验 | 容器安全下限（C9）· 钩子失败可断言（`smoke/hook-failures`）· 业务能力崩溃按失败处理（`make capabilities-selftest` 的退出码/超时用例） |
| 上层实现后才能验 | 「每租户一容器」「一个插件崩溃不影响其它会话」——需要编排层真的有多个租户在跑 |

### 2.6 成本与审计

| | 内容 |
|---|---|
| 基座给 | 次数与时长归因（§1）；轨迹本身的完整审计面（12 类事件 + 四个摘要 + 审批/钩子失败/结束标记） |
| **上层义务** | 拿**单价表**把次数/token 换成钱（基座不给价格，也不猜）；出账、配额、告警；脱敏外发 |
| 今天能验 | 「按 run 能归因次数与时长」`make cost-report`；「轨迹里没有 token 时说没有」（实测该运行时不透出） |
| 上层实现后才能验 | 成本数字是否正确；脱敏规则是否生效（需要上层的外发实现） |

## 3. 什么时候该回头改基座（而不是各写一份）

出现下面任一情形，说明**缺的是一条基座接缝**，应当改这份约定与基座，而不是放进每个上层项目各写一份：

1. 上层需要"一次调用里跑多个会话"或"运行期动态改预算" ⇒ 需要新的接缝（当前的 `loop:` 与 session 都是"一次运行"粒度）。
2. 上层需要把**身份**贯穿到轨迹/审批 ⇒ 应当由基座定义身份入口（平台变量 + 轨迹字段），而不是各项目自己塞环境变量。
3. 某个运行时开始透出 **token 用量** ⇒ 填进已预留的 `model.request.usage`，归因代码不必改（`core/trace/usage.mjs` 已按"有就汇总、没有就说没有"实现）。
4. 出现**委派工具**（子智能体）⇒ 需要给轨迹加父子关联字段，才谈得上"委派深度可断言"（见 E6 的划界）。
5. 上层要做**脱敏外发** ⇒ 需要基座提供"脱敏钩子 + 可验证的判据"（今天没有）。

## 4. 明确不承诺（读到这条请当真）

- **不做**多租户/鉴权/配额/编排：这些是上层的服务，基座只给上表那些接缝。
- **不给成本数字**：轨迹里没有 token 就说没有（实测该运行时不透出）；基座不拿次数乘猜测单价造一个"看起来像成本"的数。
- **不保证会话跨机器一致**：会话按调用方给的目录落盘，共享存储是上层的事。
- **不替上层决定终止条件**：循环何时结束由模型与运行时决定；基座只如实记录**它是怎么结束的**。
