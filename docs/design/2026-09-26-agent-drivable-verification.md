# AI 代理的容器验证：本地迭代 + 把容器的活交给 AI

> 状态：**设计稿，未实现**。登记处：路线图 §30。
> 来源：用户提出 —— 容器作为完整环境约束太大；现在都是 AI Coding，能否**本地调试为主**，
> **需要容器验证/调试时交给 AI 去做**；但**中间的协议约定**与**框架对这种模式的有效支撑**要想清楚。

## 1. 模式

| 谁 | 在哪 | 干什么 |
|---|---|---|
| 人 | 本地（编辑器、快循环） | 改定义/技能/连接器，跑快速的闸门，肉眼调试 |
| **AI 代理** | 容器（约束大、但权威） | 构建/运行容器的验证与深度调试、读结构化结果、迭代、归因失败 |

要点：**容器的约束不落到人身上**（人要被迫进容器就很烦），但**权威结论仍来自容器**。
AI 不嫌慢、不怕约束，正好适合干这半边 —— 前提是**协议机器可读**，否则 AI 就得靠猜。

## 2. 好消息：这个协议已经有一半了（实测）

| 已有的 | 内容 |
|---|---|
| **结构化结论** | `verify --json` 顶层已有：`agent` · `harness` · `harnessVersion` · `adapterVersion` · `definitionDigest` · `artifactsDigest` · `paramNames` · `effectiveConfigDigest` · `gates[]`（逐条 check）· `usable` |
| **成败协议** | 退出码语义单一定义（`core/gates/exit-codes.mjs`）：0 通过 / 2 用法 / 10 静态 / 20 解析 / 30 探针 / 40 冒烟 / 50 崩溃 |
| **身份绑定** | 定义摘要 · 产物摘要 · 生效配置摘要 · 渲染输入摘要（`renderInputsDigest`）· 镜像同源指纹（LABEL） |
| **容器内取证** | `docker run <镜像> verify`（镜像自带闸门，离线零凭据） |

⇒ 所以**不需要从零发明协议**，缺的是四处（§3）。

## 3. 缺的四处

### ① 意图面：AI 得先知道"要验什么、哪些只能容器验"

现在这些知识散在文档里。AI 需要一个**机器可读的计划**：

```bash
make verify-plan AGENT_DIR=… --json      # 或 /project verify-plan
→ { local:   [{ id, cmd, expect }...],
    container: [{ id, why, cmd, image, mounts }...],   # why = 为什么本地做不了
    notCovered: [...],                                  # 已知覆盖不到的东西
    identity:  { definitionDigest, artifactsDigest, effectiveConfigDigest, imageInputsDigest } }
```

判据：**加一条只能在容器里成立的断言 ⇒ 它自动出现在 `container[]` 且带 `why`**；不许出现"只有文档知道"的项。
这条同时是 §26 V1（`/project`）的自然延伸 —— 同一份数据、另一个出口。

### ② 执行面：一个**受控**的容器验证入口（安全分叉，见 §5）

AI 要能自己触发，但**不该拿到任意 docker 权限**。

### ③ 结果面：出处 + 覆盖范围

`verify --json` 现在**没写出处**：同一份 JSON 看不出是宿主跑的还是容器跑的、也没说哪几条断言这次没覆盖
（安全下限 / 双架构 / 同源摘要只在容器/构建侧成立）。⇒ 每条结论都要带：

```json
{ "where": "host" | "container", "image": "<tag>@sha256:…",
  "covered": ["static","resolution","probes","smoke"],
  "notCovered": ["security-floor","dual-arch","images-same-source"],
  "why": "本地没有等价的 OS 级机制" }
```

### ④ 失败面：**归因分类**（这条最关键）

容器失败时，AI 必须能自己判断这是"真缺陷"还是"环境差异"：

| 分类 | 依据 | 处置 |
|---|---|---|
| `local-reproducible` | 失败点不涉及已声明差异 | 回本地修（这是真缺陷） |
| `declared-env-difference` | 命中 `env-exemptions.yaml` 里已声明的差异 | 不当缺陷；若措辞是"本应本地也能预检"，则**本地预检漏了**（那是基座 bug） |
| `unknown` | 既不在差异清单、也复现不出来 | **必须响亮上报**，不许 AI 自行猜（这正是静默失败的温床） |

⇒ 这条把 §28 的 Q1/Q2（差异清单 + 本地预检）从"可选优化"变成**这个模式的前提**：
差异清单必须**机器可读**，否则 AI 会把"环境差异"当"代码 bug"追一整天。

## 4. 与既有章节的关系

- **§26（`/project`）**：意图面的现成载体 —— `/project verify-plan` 与 `/project bundles` 同源同逻辑。
- **§28（环境一致性）**：从"给人看的差异清单"升级为"**给 AI 读的差异清单 + 归因依据**"；Q1/Q2 成为本模式的前提。
- **§29（开发者容器）**：降为**可选**的第三种形态（人想进容器时有路），不再是主路 —— 因为本模式把人解放出来了。

## 5. 安全边界：绑定面 = **当前项目**（用户已定）

用户明确："当然不会把主机的根绑定到容器，绑定的应该是当前项目。"
⇒ §5 原来的 A/B/C 分叉**收敛**为：**受控入口 + 绑定面由基座按项目生成**，不需要再选。

**挂什么（allowlist，全部由基座生成，调用方不能拼 docker 参数）**：

| 挂什么 | 模式 | 为什么 |
|---|---|---|
| **当前项目**（智能体定义目录） | **ro**（验证）／ rw（仅显式 dev 模式） | 验证不该写项目；写只发生在容器侧的暂存与产物 |
| （可选）产物根 → `/opt/agent-base/artifact` | ro | 已有路径：宿主渲染好、容器只验（见 5.1） |
| 基座工具链 | **不挂** | 镜像自带 `gates/`（`tools/` + `core/` + `adapters/` + `node_modules/`） |
| 宿主 `node_modules` | **不挂** | macOS 原生模块进 Linux 容器会炸（`yaml`/`ajv` 恰好纯 JS 才没炸） |
| docker socket · `--privileged` · `--net=host` · `--cap-add` · `--pid=host` · `-v /` | **拒绝** | 受控入口只接受"验哪个项目、哪个 harness、哪个 arch" |

**必须有的负例判据**（否则"受控"只是口号）：
1. 调用方试图附加 `-v /:/host`、`--privileged`、socket 挂载 ⇒ **拒绝并说明原因**；
2. 项目目录里放一个指向 `/` 的符号链接 ⇒ 挂载源**用 realpath 校验**，逃不出项目子树；
3. 试图把项目目录挂成 rw 来"验证" ⇒ 拒绝（验证只读；要写请显式走 dev 模式）。

### 5.1 实测（本机跑出来的，用来定 A2 的形态）

| 尝试 | 结果 | 结论 |
|---|---|---|
| 只挂**智能体定义**（ro）+ `--network none`，容器内渲染 | ✅ 渲染成功（镜像里 `gates/adapters/pi/render.mjs` 可用） | 容器**不需要**挂整个仓库；基座工具链在镜像里 |
| 容器内跑 `tools/verify.mjs`（宿主入口） | ❌ **2 个假失败**：`docs/changelog-version`、`docs/catalog-sync`（缺仓库 `docs/`） | **A2 必须走 agent-only 入口**；这也是 A4 归因的**第一个真实案例** —— 假失败会被 AI 当成缺陷去追 |
| 挂**产物** ro + 镜像自带 `verify`（现有路径） | ✅ 闸门 2/3/4 全过（离线、零凭据） | 现有路径本来就对，受控入口应当**复用它**，不要另起一套 |

## 6. 判据（无人值守端到端一条）

> **AI 在没有任何人转述的情况下**，从"改了定义"走到"拿到可归因的容器结论"：

1. 改定义 → 本地跑快速闸门（非交互、结构化）
2. 读 `verify-plan` → 知道哪些必须进容器、为什么
3. 触发受控容器验证（方案 B）→ 拿到 `{ where, image, covered, notCovered, gates, usable }`
4. 若失败 → 按 §3④ 归因；`unknown` 必须响亮上报，不许猜
5. 全过程**不需要交互式终端**、不需要人复制粘贴

配套硬判据：
- **每一步都有非交互入口且输出可解析**（交互式终端只能作为人看的补充，不能是唯一路径）
- **同一份输入重复触发 ⇒ 结果与摘要一致**（可复现、可缓存，不做无效重跑）
- **容器结论必须能指回本地状态**（`definitionDigest` + `artifactsDigest` 绑定）
