# 12 · 开发场景演练（真实开发循环）

> 这篇回答一个问题：**"我要验证 agent-base 真的能用"该怎么做？**
> 答案不是"跑一下 `examples/`" —— 那是基座自带的**样子示例**（`examples/README.md` 自己写着
> "不是基座的一部分"），它跑零凭据假网关、验的是**契约是否成立**。
> 真实开发场景是**派生一个你自己的智能体**，然后走完整的开发循环。

## 一条命令跑完

```bash
make walkthrough                    # 离线闭环（零凭据假网关，不花任何额度）
make walkthrough LIVE=1 ENDPOINT=https://… API_KEY=…    # 再打真实端点（真的调用模型）
```

它会真的**派生一个智能体**、真的改定义、真的跑闸门与容器，最后给出功能 × 证据的清单。
默认全部离线；`LIVE=1` 才打真实端点 —— 没验的项会明确标成"跳过"，不会伪装成通过。

## 它走的循环（也就是开发者实际会走的）

| # | 步骤 | 在验什么 |
|---|---|---|
| 1 | `new-agent` 派生 | 骨架可用、含 Makefile（派生者不必碰基座） |
| 2 | 改定义：加自己的技能 + 工具边界 | 技能是 `skills/<名>/SKILL.md` **目录发现**，不在定义里列清单；`tools.deny` 生效 |
| 3 | **故意写错**（模型名、技能引用） | 闸门 1 当场变红并列出可用取值 —— 闸门真的在管事，不是摆设 |
| 4 | 改对 → 闸门 1 全绿 | 错误修掉即可交付 |
| 5 | 渲染（两次） | 确定性（digest 相同）+ 产物自带运行期参数契约 |
| 6 | 渲染清单 | 自己的技能与工具边界**真的进了产物**（不看定义文件，看产物） |
| 7 | 闸门 2 / 3 / 4 | 解析自证 · 集成探针 · 端到端冒烟（离线、零凭据） |
| 8 | 运行期参数四种给法 | ① 环境变量 ② `_FILE` ③ `AGENT_SECRETS_DIR` ④ 定义默认值 —— 都能解析、优先级正确 |
| 9 | 本地真跑 + 产物只读 | 跑完之后**产物 digest 不变**（运行期隔离成立） |
| 10 | 跨运行时比对 | 同一份定义在 pi / dsh 上等价，差异必须有声明 |
| 11 | 容器 `config-check` | 镜像里能配好 LLM 并离线自检；**缺凭据 fail-fast** |
| 12 | （可选）`LIVE=1` | 对真实端点跑四道闸门 —— "真的能用"的最终证据 |

## 什么时候用 `examples/`

| 你想要 | 用什么 |
|---|---|
| 看"这东西长什么样"、抄一份写法 | `examples/`（`idea-to-proof` 纯技能型 · `contract-review` 带 MCP 连接器） |
| 验证基座自身是否健康 | `make validate` / `make conformance` / 各 `*-selftest` |
| **验证"我的场景能不能用"** | `make walkthrough`，然后把工作区里的定义换成你自己的 |

`examples/` 的价值在**对照**：同一份定义在两个运行时上等价、连接器怎么声明、技能怎么组织。
它不是你的项目的起点 —— 起点是 `make new-agent`。

## 没验的部分（诚实清单）

- **真实模型质量**：演练只验"调用成功、工具字段没被吞、流式没被降级"，不评价回答好不好。
- **LIVE**：需要你自己给端点与凭据；订阅读（如 `openai-codex`）请先登录，见 `01-quickstart`。
- **镜像**：容器那两步要求本机已构建镜像（`make image-all`），没构建会标成"跳过"。
- **推送与编排**：`image-push` 未对真实 registry 验证；本项目不假定统一 K8s。
