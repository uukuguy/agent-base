# 先建地图，再动手

改代码最常见的浪费是**在错误的文件里读半天**。这个技能只做一件事：用**可执行的方式**把地图建出来，
而不是靠猜或靠通读。

## 顺序（每一步都有命令，不许跳过前一步直接改）

1. **入口在哪** —— 从名字/路由/命令行/导出点找入口，而不是从目录名猜：
   ```bash
   rg -n "registerTool|createServer|addEventListener|export function main" --type js -g '!node_modules' .
   ```
2. **谁调用谁** —— 找出目标符号的**所有**引用点，先看调用方再看实现：
   ```bash
   rg -n "\b目标符号\b" -g '!node_modules' .
   ```
3. **数据怎么流** —— 顺着调用链读**参数与返回值**（它们比函数体更能说明职责）：
   一个函数的参数就是它的契约；返回值就是它对世界的承诺。
4. **边界在哪** —— 找到错误处理与校验点。**改动的正确落点通常是边界**，不是最内层。
5. **写完地图再动手** —— 地图就是：入口 → 中间层 → 落点 → 边界，四段都要能说出**文件名 + 行为**。

## 三条纪律

- **不读整个文件就下结论**：用 `rg -n` 定位后再读上下文（前后 20 行通常够）。
- **不靠目录名推断职责**：名字会骗人，调用关系不会。
- **不在没建立地图前改代码**：改错层的代价通常是"看起来修好了，其实复制了一份逻辑"。

## 完成时会是什么样

你能一句话说清：`入口在 A，经由 B 调到 C，边界在 D；我要改的是 C（或 D），因为……`。
说不出来就说明地图还没建完 —— 继续第 2 步，别开始改。
