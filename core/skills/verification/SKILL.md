# 证据先于断言

"应该没问题"不是结论。这个技能只要求一件事：**每个"完成"都配一条能重跑的命令 + 它的实际输出**。

## 声称之前，先回答三个问题

1. **判据是什么** —— 什么东西从"不满足"变成"满足"？说不出来就说明还没定义完成。
2. **怎么跑出来** —— 一条命令（含退出码）。跑不了 ⇒ 这不是"没时间"，是**没判据**。
3. **它证明了什么、没证明什么** —— 例：`make verify` 全绿证明四道闸门过了，
   **不证明**镜像里也过（容器专有的那几类要另跑）。把"没证明的"也说出来。

## 四条纪律

- **跳过 ≠ 通过**：跳过的项要如实标"没验"，不许算进"全绿"。
- **本地 ≠ 交付结论**：本地过只说明本地过；环境差异要么消掉，要么**显式声明**。
- **一次失败就停**：第一个失败闸门之后的结论没有意义（前面的错了，后面的都在错的前提上）。
- **留档**：把命令与输出（哪怕只是退出码）留在你能再找到的地方 —— 下次复算不用重新想。

## 反面清单（这些都不算验证）

- 只看代码"读起来对"；只跑了一次没重跑；用"之前是好的"当证据；
- 在没跑的情况下说"应该过了"；把别人的结论当自己的验证。
