# 先复现，再二分，最后才修

排障最大的浪费是**在没复现的情况下改代码**：改完不知道好没好，于是越改越乱。
这个技能的顺序是硬的：**没复现就不二分，没二分就不修**。

## 1. 复现（这一步没完成，后面全是猜）

- 把现象压成**一条命令**：退出码、关键输出、耗时。写不出这一条就说明还没复现。
- 现象时有时无 ⇒ 先固定变量（时间、随机种子、并发度、环境变量），让它**稳定地失败**。
- 复现不了时**如实说"无法复现"**并列出已固定的变量 —— 不要用"看起来像"当结论。

## 2. 二分（缩小到一层）

- **先删再加**：把可疑输入/配置逐段删掉，看现象是否消失（比"逐个加"快得多）。
- **在边界处打点**：每个进程/模块边界打印一次"进去了什么、出来了什么"，
  找到**第一个**与预期不符的地方 —— 那里才是根因所在层。
- **一次只改一个变量**：同时改两个，你就失去归因能力。

## 3. 修（改最小的那一处）

- 改**根因所在层**，不要在下游加兜底：兜底会把根因留成定时炸弹。
- 修完**跑第一步那条命令**确认：前后两次输出都要留档（这是"修好了"的唯一证据）。
- 顺手补一条**能自动复现这个 bug 的测试**；没有它，下次还会回来。

## 三条不许做

- 不许"改了看看"（没有假设的改动）；
- 不许静默降级（捕获异常后继续跑，把失败变成"看起来正常"）；
- 不许在没复现时声称修好。
